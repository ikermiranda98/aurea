# A3 — Translator MT5 (`bots-mt5.ts` + `mt5-ordenes.ts`)

## 1. Propósito

Portar 1:1 el traductor que convierte las llamadas `ib_async` de los bots en operaciones MetaTrader 5 sobre el puente Python del enlace: resolución de instrumentos, matemática de lotes que preserva exposición, órdenes DEAL/PENDING/SLTP/CLOSEVOL/DELETE, OCA, reintentos, reconciliación de fills y el cierre manual de un símbolo. Es la pieza que hace que un bot escrito para IBKR opere en MT5 sin cambiar una línea.

## 2. Comportamiento exacto observado en el código TS

### 2.1 Constantes y matemática de lotes (`bots-mt5.ts`)

- `RETENCION_MS = 14 * 86_400_000` (`:33`); `DIA_MS = 12 * 3_600_000` (`:35`); `GRACIA_MS = 6_000` (`:37`).
- `ACTIVOS = {PendingSubmit, PreSubmitted, Submitted}` (`:27`); `REINTENTO = {-1, 10004, 10018, 10020, 10021, 10024, 10031, 10012}` (`:29`); `CRUZADO = {10015, 10016}` (`:31`).
- `lotesPorUnidad(i)` (`:73-77`): forex → `1 / max(contractSize, 1e-9)`; si no → `porLote = tickValue / tickSize`; `porLote > 0 ? multiplier / porLote : 1`.
- `lotes(i, qty)` (`:80-86`): `paso = volumeStep > 0 ? volumeStep : 0.01`; `v = round(|qty| * lotesPorUnidad / paso) * paso`; si `v < volumeMin && |qty| > 0` → `v = volumeMin`; si `volumeMax > 0` → `min(v, volumeMax)`; `redondear(v, 8)`.
- `unidades(i, lots)` (`:89-93`): `u = lots / lotesPorUnidad`; `r = round(u)`; si `|u-r| < 1e-6` → `r`, si no `redondear(u, 6)`.
- `precioDe(i, p)` (`:95-96`): redondeo al tick; decimales `min(max(digits,0),10)`.
- `redondear(valor, digitos)` (`:67-70`): `round(valor * 10^d) / 10^d`.
- `magicPorDefecto(sistema)` (`:171`): `7_700_000 + parseInt(sistema)`.
- `conIdDe(root)` (`:205-212`): FNV-1a 32-bit sobre los bytes UTF-8, `(h & 0x3fffffff) + 100_000` → estable entre máquinas.

### 2.2 Resolución de instrumentos (`:184-401`)

- `FUTUROS` (`:184-199`): roots con `[multiplier, [símbolos MT5]]` — MNQ 2/NASDAQ, NQ 20, MES 5, ES 50, M2K 5, RTY 50, MYM 0.5, YM 5, MGC 10/ORO, GC 100, SIL 1000, SI 5000, MCL 100, CL 1000. Listas: `NASDAQ`, `SP500`, `RUSSELL`, `DOW`, `ORO`, `PLATA`, `PETROLEO` (`:175-181`).
- `SUFIJOS = ["", ".cash", ".a", "m", ".m", ".pro", ".raw", "+", ".i", "_i"]` (`:202`).
- `resolver(...)` (`:357-401`): si no es futuro y `root` encaja en `/^[A-Za-z]{6}$/` → `forex`. Nombres candidatos: primero el `symbol` de `system.json` (si lo hay) y luego `base+sufijo` para cada base. Por cada nombre, comando `SYMBOL`; el primero con `ok` y `data` objeto gana; si `retcode` es -1/-2 → error inmediato. Campos: `conId=conIdDe(root)`, `secType = sec || (forex ? "CASH" : "FUT")`, `currency = currency || spec.currency_profit || "USD"`, `multiplier = futuro?.[0] ?? 1`, `mt5 = spec.symbol`, `digits/contractSize/tickSize/tickValue/volumeMin/volumeStep/volumeMax` (default digits 5).
- `qualify` (`:404-425`): si `conId !== 0` y no llega `symbol`, devuelve el instrumento conocido (re-resuelve si cambió de cuenta); si no, `root = (sec CASH/CFD) ? (sym+currency si 3+3, si no sym sin puntos) : sym`, y `resolver`.
- `contratoJson(i, secType)` (`:340-355`): `symbol/currency` separados para forex de 6 letras; `multiplier = forex ? "" : String(multiplier)`; `localSymbol = i.mt5`; `tradingClass = i.root`; `lastTradeDateOrContractMonth = ""`; expone `mt5` y `lotsPerUnit`.

### 2.3 Barras, posiciones y cuenta (`:428-505`)

- `MARCOS` (`:237-255`): `"1 min"→M1` … `"1 hour"/"1 hours"/"60 mins"→H1`, `2/3/4/8 hours`, `1 day→D1`, `1 week→W1`.
- `duracionSegundos(d)` (`:258-277`): `S` segundos; `D` = `(n + 2*floor((n+4)/5) + 1) * 86400` (días de trading, suma fines de semana); `W` = n*7*día; `M` = n*31*día; `Y` = n*366*día; si no → null.
- `bars` (`:428-443`): `RATES <mt5>;<tf>;<hasta-lapso>;<hasta>`; array vacío si `data` vacío y retcode no -1/-2 (como TWS sin historia).
- `positions` (`:446-470`): por instrumento calificado en la cuenta del enlace; filtra `magic` y `mt5`; neto de lotes; `position = unidades(|neto|) * sign(neto)`; `avgCost = media * (forex ? 1 : multiplier)`; `account = nombreCuenta` (`DU<login>` si demo, si no `U<login>`, `:334-338`).
- `accountSummary` (`:473-497`): tags `NetLiquidation`, `TotalCashValue`, `EquityWithLoanValue`, `AvailableFunds`, `ExcessLiquidity`, `FullInitMarginReq`, `InitMarginReq`, `MaintMarginReq`, `UnrealizedPnL`, `BuyingPower = margin_free * leverage`, `AccountType = PAPER|INDIVIDUAL`; valor `toFixed(2)`.
- `hello` (`:499-505`): `{system, accounts:[nombre], account: enlace, magic, broker:"mt5", serverTime: Date.now()}`.

### 2.4 Cola de exclusividad (`:297-311`)

- `enExclusiva(trabajo)` encadena sobre una promesa `cola`: colocar, cancelar y reconciliar nunca se intercalan. `ocupado` sirve para que `tick` se salte si hay una acción en curso (`:873-874`).

### 2.5 Órdenes

- `netoDe(o, magic)` (`:549-558`): neto de posiciones MT5 (magic+symbol); si ~0, usa las ejecuciones de los últimos 15 s (botones/side) convertidas con `lotesPorUnidad`.
- `ejecutarMercado(o, i, magic)` (`:561-604`): `falta = lotes(i, qty - filled)`; cierra primero las posiciones opuestas **más antiguas primero** con `CLOSEVOL ticket;volumen` (retcode 10036 = ya cerrada, se ignora); si no hay fallo y `falta >= paso/2`, `DEAL symbol;buy|sell;falta;magic;comment`; si todo va bien `filled = max(filled, qty)`, `status = Filled`; si `REINTENTO` → `nextTry = now + 10 s`, `status = Submitted`; si no → `Cancelled` (si filled>0) o `Inactive`.
- `ponerEntrada(o, i, magic)` (`:607-629`): `PENDING symbol;lado;stop|limit;lots;precio;magic;comment;day(1|0)`; si `CRUZADO` → ejecuta a mercado; si `REINTENTO` → espera; si no → `Inactive`.
- `place` (`:742-839`): valida acción/tipo/cantidad; si `orderId` existe y está activo → modificación: entrada con precio/cantidad distinto → `DELETE` + re-`ponerEntrada`; salida → guarda y `proteger`. Si no existe: asigna `orderId` (el pedido si no colisiona, si no `siguiente`), `role` según `netoDe` (`market`, `entry`, `exit_sl`, `exit_tp`), guarda y ejecuta.
- `proteger` (`:651-739`): (1) books de deals `sl`/`tp` desde `min(creadas)` no usados; (2) si no quedan posiciones, cancela las salidas activas (OCA huérfanos); (3) aplica SL/TP a cada posición con tolerancia `max(tickSize/2, 1e-9)` y throttling de 3 s por ticket (`sltpEnviado`); si MT5 rechaza por precio cruzado y el precio actual toca el nivel → `CLOSEVOL` inmediato y book.
- `cancel` (`:842-862`): entrada con ticket → `DELETE`; salida → `quitarProteccion` (quita SL o TP de cada posición si no queda otra salida activa).
- `cancelarTodo` (`:935-953`): `DELETE` de entradas con ticket (10036 ignorado), marca `Cancelled` con mensaje "pánico"; devuelve `{canceladas, fallos}`.
- `sistemaParado` (`:924-931`): marca `Cancelled` las órdenes `market` activas del sistema ("el sistema se paró").
- `tick` (`:873-921`): órdenes `market` con `tif DAY` de más de `DIA_MS` → `Cancelled`; reintentos cuando `now >= nextTry`; entradas con ticket 0 → `ponerEntrada`; entradas con ticket → fills por deals con `order == ticket`, si no está pendiente y tiene filled → `Filled`, si no está pendiente y pasó `GRACIA_MS` → `Cancelled`; el resto → `proteger` por grupo `account|system|conId`.
- `podar` (`:864-869`): borra órdenes inactivas con `updated < now - RETENCION_MS`; ejecuciones con `time < ahora - RETENCION_MS`; `sltpEnviado` con 60 s.

### 2.6 Persistencia (`trading.ts:1513-1580`)

- `crearTraductor` recibe `ordenes`, `ejecuciones`, `instrumentos` cargados de `trading_bot_order`, `trading_bot_fill` y `trading_meta["bots-mt5-instrumentos"]`; filtra por `RETENCION_MS` (14 días) y `activa`.
- Callbacks `guardarOrden` (upsert por `orderId`), `guardarEjecucion` (`INSERT OR IGNORE` por `execId`), `guardarInstrumentos` (JSON en `trading_meta`).
- Arranque: borra órdenes `Filled|Cancelled|Inactive` con `updated <= now-RETENCION_MS` y fills con `time <= ahora-RETENCION_MS` (`:1574-1580`).

### 2.7 Puente Python (`mt5.ts:261-715`)

- `PUENTE_PY` se pasa con `python -c`; args `--login`, `--server`, `--desfase <fichero>`.
- `Reloj` (`:314-370`): offset servidor-UTC en segundos, redondeado a 900 s, persistido en `--desfase`; si no hay tick fresco, `desfase()` con símbolos 24/7.
- Verbos (`:443-445`, `:489-593`): `SYMBOL`, `RATES`, `DEAL`, `PENDING`, `CLOSEVOL`, `SLTP`, `DELETE`. Cada comando de orden comprueba `account_info().login == LOGIN` y `server == SERVIDOR` (retcode -3), y `terminal_info().trade_allowed` (retcode -10).
- `linea_bots` (`:598-639`): emite `type:"bot"` con posiciones (ticket, magic, sl, tp), pendientes y deals de 3 días **sólo cuando cambia la firma** (tickets de posiciones+pendientes) o cada 2 s.
- `cuenta` (`:374-430`): `balance`, `equity`, `profit` (flotante), `margin_free`, `margin_used`, `pnl_day` (realizado de deals + flotante), `positions`, `closes` (deals OUT/INOUT/OUT_BY).
- `estado` (`:293-295`): `{type:"estado", conectado:false, motivo}`.
- El puente **nunca abre** el terminal en modo enlace (`terminal_abierto()` antes de `initialize`, `:684-690`); el modo `--probe` sí puede abrirlo (`:670-674`).

### 2.8 Cierre manual (`mt5-ordenes.ts`)

- `ORDEN_PY` (`:22-115`): `terminal_abierto()` → si no se puede leer la lista de procesos, `None` y no se adjunta; `mt5.initialize()`; comprueba `cuenta.login/server`; `terminal_info().trade_allowed`; `symbol_select`; por cada `positions_get(symbol)`: `TRADE_ACTION_DEAL` con `position=ticket`, `type` opuesto, `price = bid|ask`, `deviation=20`, `magic=70910`, `comment="manual close"`, `type_time GTC`, filling FOK/IOC/RETURN según `filling_mode` (`:30-37`).
- `ordenMT5` (`:118-146`): `spawn` con timeout 30 s; la respuesta es la **última línea JSON** `{ok,message}`; si no es legible → `{ok:false, message:"...respuesta legible..."}`.
- Retcodes de `enviar` (`:39-54`): DONE/PLACED/DONE_PARTIAL → ok; CLIENT_DISABLES_AT, MARKET_CLOSED, NO_MONEY, INVALID_VOLUME → mensajes en español.

## 3. Edge cases y condiciones de error

- **Exposición**: `lotes` respeta `volumeMin/Step/Max`; los residuales de redondeo `< paso/2` se consideran hechos (`:567`, `:580`).
- **Forex**: `lotesPorUnidad = 1/contractSize` → 100 000 unidades = 1 lote; `avgCost` no se multiplica.
- **REINTENTO** (mercado cerrado, sin precios, ocupado): `nextTry = now+10 s`, `status Submitted`; no se marca fallo.
- **CRUZADO** (precio ya pasó el stop/limit): se ejecuta a mercado; en salida, si el precio ya tocó el nivel, cierra a mercado.
- **10036** (posición/orden ya no existe): se ignora en CLOSEVOL/DELETE y en el cierre manual.
- **DAY**: una orden a mercado que no ejecuta en 12 h → `Cancelled`.
- **GRACIA_MS**: si un pending desaparece de MT5 sin fill, se marca `Cancelled` tras 6 s (antes se desconfía).
- **Firma del libro**: el traductor no ve desaparecer una posición antes que su deal (el puente sólo envía deals cuando cambia la firma).
- **Cola en exclusividad**: `tick` no corre si hay una acción `ocupado`; `place`/`cancel`/`cancelarTodo` son seriales.
- **Retención**: 14 días; el arranque poda.
- **magic**: por defecto `77000NN`; el `system.json` puede fijarlo.
- **Terminal ajeno**: si el terminal está en otra cuenta, el puente responde -3 y no envía nada.
- **Algo Trading desactivado**: retcode -10, no se envía.
- **Cierre manual**: nunca abre el terminal; si está cerrado, falla sin enviar.

## 4. Mapeo TS→Rust

- **Módulos**: `crates/trading/src/mt5/mod.rs` (translator), `instruments.rs`, `lots.rs`, `ordenes.rs`; el puente Python (`PUENTE_PY`, `ORDEN_PY`, `TERMINAL_ABIERTO_PY`, `bots-py.ts`) se conserva como recurso embebido (`include_str!`) y se escribe en `%APPDATA%\Aurea\bots-mt5\` (plan §5.2).
- **Estado del traductor**: un actor con `tokio::sync::Mutex<TraductorState>` (el equivalente de `enExclusiva`) + `mpsc` para comandos; `tick` con `tokio::time::interval(1s)`. `ocupado` → un `bool` protegido por el mismo mutex.
- **Comandos al puente**: `tokio::process::Child` con `stdin` pipe y `stdout` leído por `tokio::io::BufReader::lines()`; `comandoMT5` (`trading.ts:1464-1483`) con `esperando: HashMap<id, oneshot::Sender>` y timeout 30 s (retcode -2).
- **Librería de lotes**: funciones puras `lotes_por_unidad`, `lotes`, `unidades`, `precio_de`, `con_id_de` (FNV-1a) — port 1:1, decisivas para los tests.
- **Persistencia**: `trading_bot_order`/`trading_bot_fill`/`trading_meta` vía `rusqlite` (A1); `OrdenVirtual`/`Ejecucion`/`Instrumento` como structs `serde`.
- **`netoDe`**: posiciones MT5 del enlace + ejecuciones de 15 s; el enlace se resuelve con `enlaceBot` (`trading.ts:1486-1506`).
- **`cerrarMT5`** (`trading.ts:3400-3424`): si no hay `libro`, invoca `ordenMT5` (one-shot); si hay, `CLOSEVOL` por ticket.
- **`sistemaParado`/`cancelarTodo`**: los llama A2/A4.
