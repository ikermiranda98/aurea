# A4 — Ciclos de cierre + claims + veredictos + panic

## 1. Propósito

Portar el camino que mueve dinero: `closePosition` (una posición), `closeAllPositions` (barrido), `panic`, y el sistema de **claims duraderos** que hace que una repetición del mismo `requestId` devuelva el veredicto anterior en lugar de duplicar órdenes. Incluye el fallback OCA de dos límites GTC a ±4 ticks sobre la rejilla del contrato, la cancelación de órdenes propias antes del envío, el aborto ante órdenes ajenas y el veredicto fail-closed cuando la DB no responde.

## 2. Comportamiento exacto observado en el código TS

### 2.1 Registro de claims y veredictos en memoria

- `cierresEnVuelo: Set<conId>` (`trading.ts:662`): un cierre en vuelo por contrato; se borra con `Effect.ensuring` (así una interrupción no deja el contrato bloqueado).
- `cierresRecientes: Map<clave,{ts,salida}>` (`:663`): replay por `requestId` durante **60 s** (`repetirVeredicto`/`recordarVeredicto`, `:3257-3264`); la limpieza expira entradas antiguas.
- `VIGENCIA_RECLAMO_MS = 5 * 60_000` (`:668`); `VIGENCIA_VEREDICTO_MS = 24 * 60 * 60_000` (`:670`).
- `selloAnonimo()` (`:674-675`): `` `${Date.now()}-${process.pid}-${contadorSello++}` `` para ids anónimos únicos.
- Tipos `ReclamoCierre` (`:681-686`): `repetida | vestigio | ajena | nueva | fallida`.

### 2.2 Reclamo duradero (`reclamarCierreDb`, `:3311-3364`)

Id de fila: `cierre:<requestId>` (o `cierre:<symbol>:<sello>` anónimo; `cierre-todo:<requestId>` para el barrido; `cierre-todo:<requestId>:<symbol>` para los hijos). `lockKey` = `symbol` en IBKR, `mt5:<login>@<server>:<symbol>` en MT5; la fila masa usa `lock = null`.

Dos pasadas:
1. Lee la fila propia por `id`:
   - `verdict != null` → `repetida` con el JSON parseado (si el JSON está roto → `fallida`).
   - `verdict == null` y `now - ts < 5 min` → `vestigio` con `veredictoOcupado` (la submission sigue viva; no reordena).
   - `verdict == null` y pasado el window → escribe `veredictoVestigio`, `lock = null`, `ts = now`, y devuelve `vestigio` (la submission nunca reordena por encima).
2. `INSERT ... ON CONFLICT DO NOTHING RETURNING id`; si inserta → `nueva`.
3. Si no inserta: lee al tenedor por `lock`. Si no existe → siguiente pasada. Si `now - tenedor.ts < 5 min` → `ajena`/`Ocupado`. Si está viejo → absorbe (escribe `vestigio`, libera lock) y repite.
4. Dos pasadas perdidas → `ajena`/`Ocupado` (una sesión rival reclama el mismo id al mismo tiempo; rechazar no compite).
- Cualquier excepción de DB → log `trading.log.close.claim_failed` y `fallida` (`:3360-3363`). **Fail-closed**: el llamador obtiene `veredictoDbCaida` y no cierra.

### 2.3 Finalizador (`finalizarCierreDb`, `:3371-3388`)

Se ejecuta con `Effect.onExit`: escribe `verdict = JSON(exit success ? exit.value : veredictoInterrumpido)` y `lock = null`, `ts = now`. Si la DB falla, sólo log (`trading.log.close.verdict_failed`): el veredicto del ciclo llega igualmente a su llamador.

### 2.4 Rejilla de ticks

- `ticksPorConId: Map<conId, minTick>` (`:638`), rellenado al re-resolver el contrato (`:2944-2947`).
- `TICKS_DEFECTO` (`:637`): MNQ 0.25, M2K 0.1, MGC 0.1, USDJPY 0.001. `tickDeContrato(conId,symbol)` (`:642-647`): el propio si es finito y > 0; si no el de la familia (`familiaDe`, `:625-631`); si no MNQ.
- `enRejilla(precio, tick)` (`:650`): `Number((round(precio/tick)*tick).toFixed(9))`.
- `textoPrecio` (`:653-657`): decimales del tick, máx 6.
- `familiasRastreo = ["MNQ","M2K","MGC","USDJPY"]` (`:620`).

### 2.5 `cerrarUna(posicion, cuenta)` (`:2900-3253`)

Orden de guardias:
1. `!enlacePrimaria.conectado` → `trading.close.no_tws` (`:2902-2905`).
2. `posicion.size > 0`; si no → `trading.close.no_size`.
3. `contrato = contratos.value.get(symbol)`; si falta o no tiene `conId` → `trading.close.no_contract`.
4. `cierresEnVuelo.has(conId)` → `trading.close.busy` (log `busy_contract`).
5. Si `!contrato.exchange || contrato.exchange === "SMART"`: re-resuelve por `conId` con `getContractDetails({conId, symbol, secType, lastTradeDateOrContractMonth, strike, right, multiplier, currency, exchange:""})`; busca el detalle con el mismo `conId`; captura `minTick`; si falla → `trading.close.def_failed`/`def_incomplete`. Aplica `contratoParaOrden` (`:592-595`: recorta la fecha a `YYYYMMDD`).
6. Lee órdenes abiertas (`getAllOpenOrders`): `activasDeEste` = mismo `conId` y status no terminal (`TERMINACIONES = {Filled, Cancelled, ApiCancelled, Inactive}`, `:2853-2858`). `propiaRef` = `orderRef` empieza en `escritorio-cierre`.
   - Si hay ajenas → **abortar** con `trading.close.foreign_orders` (nada se cancela).
   - Si hay propias: `cancelOrder` de cada una, `sleep(500)`, relee; si quedan → `trading.close.cancel_pending` (abortar, no enviar).
7. **Relectura de la posición** (`posicionesDeMotor(cuenta)`, la cuenta fijada arriba): si desapareció → `gone_while_prep` (ok); si cambió lado o tamaño → `changed_while_prep` (abortar).
8. Orden de mercado: `action = side === "long" ? SELL : BUY`, `totalQuantity = size`, `MKT`, `tif DAY`, `orderRef = escritorio-cierre-<conId>-<sello>`, `outsideRth: true`, **`transmit: true`**, `account: cuenta`. `placeNewOrder` (`:3061`). `ordenesPropias.add(id)`.
9. Espera: hasta 20 pasos de 250 ms con `refrescarOrden(id, ref, cantidad)`; `posiciónFuera()` (la posición deja de aparecer) cuenta como `Filled`; rompe al llegar a un estado terminal.
10. `Filled` → `trading.close.executed_market` (ok).
11. Si sigue viva o desconocida: `cancelOrder(idMercado)` y otros 20×250 ms; `Filled`/`posiciónFuera` → `trading.close.executed_order`; si sigue sin confirmación → `trading.close.market_not_cancelled` (sin límites, para no doblar).
12. `restante = cantidad - min(cantidad, llenado)`. Relectura final: si la posición desapareció → `closed_during_wait`; si cambió de lado → `side_changed_wait` (sin límites); `restante = min(restante, vivaFinal.size)`.
13. `precioActual = vivaFinal.current ?? posicion.current`; si es null → `no_price_for_limits`.
14. `salto = tick * 4`; `arriba = enRejilla(precio + salto)`; `abajo = enRejilla(precio - salto)`; exige `abajo > 0 && arriba > abajo` si no → `invalid_limits`.
15. Dos límites: `LMT`, `tif GTC`, `orderRef = escritorio-cierre-limite-<conId>-<sello>`, `outsideRth`, `ocaGroup = cierre-<conId>-<sello>`, `ocaType: 1`, `transmit: true`, `account`. `sleep(500)` y refresco de cada uno.
16. `aceptados` = ids con estado no terminal; si ninguno aceptado y ninguno con id → `market_failed_no_limits`; si todos con id fueron rechazados → `market_failed_limits_rejected`; si 1 aceptado → ok con un límite; si 2 → ok con OCA.

### 2.6 `refrescarOrden` (`:2873-2887`)

- `getAllOpenOrders`: busca `orderId` **y** `orderRef` → actualiza status/filled.
- Si no está: `getExecutionDetails({clientId: String(clienteMotor)})`, filtra por `orderId` y `orderRef`, suma `shares`; si `llenado >= cantidad` → `Filled`.

### 2.7 Veredictos (`:3269-3300`)

- `veredictoVestigio(symbol)`: `ok:false`, `trading.close.vestigio`, message "The previous close of X left no verdict: its session died mid-cycle…".
- `veredictoInterrumpido(symbol)`: `trading.close.interrupted`.
- `veredictoOcupado(symbol)`: `trading.close.busy` ("A close is already running…").
- `veredictoDbCaida(symbol)`: `trading.close.unverified` ("the database is unavailable, so the close was not sent").
- No existe una función `veredictoCierre`: los veredictos de ciclo se construyen inline en `cerrarUna` con sus `message_key` (`trading.close.*`).

### 2.8 `closePosition(symbol, requestId?)` (`:3445-3553`)

1. `clave = requestId ? "cierre:"+requestId : null`.
2. **Guardas AE-012 antes del replay**:
   - puente MT5 del `cuentaActiva` caído → `trading.close.mt5_bridge_down`;
   - cuenta activa MT5 sin ese símbolo → `trading.close.account_no_symbol`;
   - cuenta activa IBKR que no es el enlace primario (watch) → `trading.close.readonly_account`.
3. Replay 60 s por `clave` (si lo hay).
4. `lockKey` según la cuenta activa (MT5 `mt5:login@server:symbol`; IBKR `symbol`).
5. `reclamarCierreDb`; `fallida` → `veredictoDbCaida`; no `nueva` → log y `reclamo.salida`.
6. Ciclo: re-chequea puente MT5 caído; MT5 con posiciones → `cerrarMT5`; MT5 sin el símbolo → `account_no_symbol`; watch IBKR → `readonly_account`; `!primary.conectado` → `no_tws`; `cuenta === null` → `no_account`; `posicion` → `cerrarUna`, si no → `sinPosicionQueCerrar`.
7. `Effect.onExit` → `finalizarCierreDb`; recuerda el veredicto en `cierresRecientes`.

### 2.9 `closeAllPositionsInterno(requestId?, conGuardas=true)` (`:3565-3686`)

- `clave = "cierre-todo:"+requestId`. Guardas de vista (salvo `conGuardas=false` para panic): MT5 → `trading.close.all_mt5_view`; watch → `readonly_account`.
- Replay; `reclamarCierreDb(idReclamo, null)` (fila masa: `symbol=""`, `lock=null`).
- Por símbolo: `cerrarConReclamo` → `reclamarCierreDb(idReclamo+":"+symbol, symbol)`; `cerrarUna` con `onExit`.
- Dos pasadas: la foto inicial y los recién llegados (un bot que abre a mitad del barrido).
- Veredicto: `fallos` = salidas `!ok`; `saltadas` = lo que sigue abierto al final; `trading.close.all_requested` / `all_partial`; el mensaje lista símbolos.

### 2.10 `panic()` (`:3697-3746`)

1. Log `trading.log.panic.start`.
2. `detenerTodos("panic")` → `detenidos`/`fallos`.
3. `traductor.cancelarTodo()` (órdenes de bots MT5; evita que un pending reabra lo cerrado).
4. Cancela **todas** las tasks `pending` (status `cancelled`).
5. `closeAllPositionsInterno(undefined, false)` (sin guardas de vista: cierra lo del motor aunque se esté viendo MT5/watch).
6. Por cada enlace MT5 conectado: `cerrarMT5ConReclamo` por símbolo (lock `mt5:login@server:symbol`).
7. Resumen: `stopped`, `fallos`, `pendientes`, `cierre.message`, `mt5`, `leftover` (símbolos aún abiertos en cuentas IBKR distintas a la del motor) → `PanicResult` con `message_key trading.panic.summary` y `message_params{stopped,failed,cancelled,close,mt5,leftover_symbols,leftover_count}`.
- Nada se re-arme: los sistemas quedan parados.

### 2.11 Cierre MT5 (`:3400-3443`)

- `cerrarMT5`: si `enlace.libro === null` → one-shot `ordenMT5(pythonMT5(), {accion:"cerrar", login, server, symbol})`; si no, por posición `CLOSEVOL ticket;volume` (retcode 10036 ignorado).
- `cerrarMT5ConReclamo`: claim `mt5:login@server:symbol` + `onExit`.

### 2.12 Houseskeeping de arranque (`:3814-3825`)

- Borra `trading_close` con `verdict IS NOT NULL` y `ts <= now - 24 h`. **Nunca borra claims abiertos** (su ausencia de veredicto es la información que usa la toma de control).

## 3. Edge cases y condiciones de error

- **Claim fresco (<5 min) del mismo id** → `vestigio`/`Ocupado`; nunca reordena.
- **Claim viejo (>5 min)** → veredicto `Vestigio`, lock liberado, y el nuevo ciclo toma el contrato; un repeat del mismo id devuelve el `Vestigio` grabado.
- **Fila masa** (`lock=null`): el unique index no la retiene; solo un `id` gemelo compite con ella, y la lectura propia resuelve por su veredicto.
- **DB caída en el claim** → `DbCaida`, no se envía nada (fail-closed).
- **DB caída al grabar el veredicto** → el ciclo entrega su veredicto al llamador; el registro avisa.
- **Órdenes ajenas** → aborta antes de cancelar nada (protege stops manuales o de otro bot).
- **Cancelaciones propias no confirmadas** → aborta sin enviar.
- **Posición que cambia lado/tamaño** → aborta; nunca envía el lado opuesto sobre una posición distinta.
- **Mercado no confirma en 5 s** → se cancela y se espera; sólo tras estado terminal positivo salen los límites.
- **Sin precio actual** → no se calculan límites.
- **`transmit` no puesto** → TWS lo lee como "hold" y descarta (error 202); por eso `transmit: true` explícito.
- **Orden propia rechazada** (código en `RECHAZOS_ORDEN`, `:583-587`) → `rechazosOrden` y estado `Inactive` inmediato; los avisos 399/2109/10349 **no** son rechazos.
- **Rechazo de divisas (201)** → explicación `EXPLICACION_DIVISAS` (`:695-697`).
- **Interruptción** (panic del Effect, apagado) → `Interrumpido` y lock liberado.
- **Panic con cuenta MT5/watch** → barre igualmente lo del motor y nombra los leftovers.

## 4. Mapeo TS→Rust

- **Claims**: `crates/trading/src/claims.rs` con `rusqlite` transaccional (`Connection::transaction`). `INSERT OR IGNORE ... RETURNING id` para el `nueva`; `UPDATE ... WHERE id=?` para vestigio/absorción; `SELECT` por `lock`.
- **Reentrada**: `cierresEnVuelo` → `tokio::sync::Mutex<HashSet<u32>>` o `DashSet`; garantizar el borrado con un guard `Drop` (equivalente de `Effect.ensuring`).
- **`cierresRecientes`** → `Mutex<HashMap<String,(Instant, PositionCloseResult)>>` con TTL 60 s.
- **`cerrarUna`** → `async fn cerrar_una(...) -> Result<PositionCloseResult, Error>`; el `onExit` se traduce con un struct guard que en `Drop` escribe el veredicto (o `Interrumpido` si no se llegó). `Effect.sleep` → `tokio::time::sleep`.
- **`refrescarOrden`** → `crates/tws` expone `get_all_open_orders()` y `get_execution_details(client_id)`; el emparejamiento por `(orderId, orderRef)` es obligatorio.
- **`tickDeContrato`/`enRejilla`/`textoPrecio`** → funciones puras en `crates/trading/src/close/ticks.rs`.
- **`panic`** → `async fn` que llama a A2 (`detener_todos`), A3 (`cancelar_todo`) y `close_all_positions_interno(false)`.
- **`posicionesDeMotor(cuenta)`** → el mapa por cuenta de A1; el cierre **nunca** lee la lista plana cuando hay mapa por cuenta (`:1176-1180`).
- **Verdadero error tipado** (`TradingError`) en lugar de panics; `ok:false` es un resultado normal (el mensaje lleva la razón).

## 6. Criterio de aceptación

> **A4** Ciclos de cierre: `closePosition` (cancelar órdenes propias primero; órdenes ajenas abortan; relectura; mercado opuesto; fallback dos límites OCA GTC ±4 ticks en grid de tick) + `closeAllPositionsInterno` + `panic` + **claims** (`cierre:<requestId>`, lock único, validez 5 min, replay 24 h, fail-closed con DB caída) + veredictos (`veredictoCierre/Vestigio/Interrumpido/Ocupado/DbCaida`). *Criterio: tests de claims/replay idénticos a Openbot.*
