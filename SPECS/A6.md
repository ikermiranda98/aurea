# A6 — Superficie de acciones del engine (firmas exactas)

## 1. Propósito

Fijar la superficie pública del motor en Rust: la firma y la respuesta de cada acción (`state`, `system_start`, `system_stop`, `task_add`, `task_cancel`, `position_close`, `positions_close_all`, `panic`, `connect`, `disconnect`, `account_select`), más el resto de la interfaz (`link_add`, `link_remove`, `mt5_detect`, `ibkr_detect`, `pool_select`, `task_list`, `snapshot`, `run`) y los guards que las envuelven. Es el contrato que el orquestador cablea a RPC y MCP.

### 2.2 Herramientas del desk (`tool/plugin/trading.ts`, 303 líneas)

- Guardián de escritorio (`:58-66`): `session.metadata["opencode.trading"] === true`; si no → `ToolFailure("The trading tools only work in the trading desk's own chat…")`. **Todas** las tools lo piden antes de tocar el engine.
- `vistaOpera` (`:96-106`): si `snapshot().account !== null` y su `link` no es `links[0].id` → `ToolFailure("The shown account (…) only reads: its positions can't be closed from the desk…")`. Se aplica a `position_close` y `positions_close_all`, **antes** de pedir permiso.
- `ask(...)` (`:72-89`): `permission.assert({action, resources, save?, metadata, source:{type:"tool",messageID,id}})`. `save` ofrece "siempre" para esa acción/recurso; las rutas de orden **no pasan `save`**, por lo que siempre preguntan.

|---|---|---|---|
| `state` | `{}` | `Snapshot` con `logs` = últimas 20 (`:127`) | ninguno (sólo desk) |
| `system_start` | `{systemID}` | `System` | `trading_system_start`, `[systemID]`, `[systemID]` |
| `system_stop` | `{systemID}` | `System` | `trading_system_stop`, `[systemID]`, `[systemID]` |

## 3. Edge cases y condiciones de error

- Fuera del chat del desk, las tools **no** piden permiso ni tocan el engine (`tool-trading.test.ts:82-105`).
- `vistaOpera` se evalúa antes del permiso: una cuenta watch no genera prompt.
- Una denegación de permiso produce `ToolFailure` con el mensaje del permission layer (`Permission denied: <action>`); el engine no se llama.
- `requestId` de chat repetido → replay del veredicto (A4).
- `closePosition` sin `requestId` (HTTP) → id anónimo con sello; sin replay entre llamadas.
- `taskAdd` inválido → `InvalidTaskError` con mensajes exactos (`:172-179`).
- `taskCancel` de task inexistente → `TaskNotFoundError`.
- `accountSelect` de cuenta desconocida → `InvalidTaskError("Unknown account: …")`.
- `linkAdd` con puerto 7496 sin `live:true` → `InvalidTaskError`.
- `linkRemove` del primario → `InvalidTaskError`.
- `connect`/`disconnect` devuelven la cuenta en ese instante (null si aún no llegaron balances).

## 4. Mapeo TS→Rust

- **Tipos**: `crates/proto` — structs `serde` con `Option` para los campos `?`; `TaskID` como newtype con prefijo `trd_` (validación en la deserialización); `PositionCloseResult`/`PanicResult`/`Snapshot` tal cual.
- **Engine**: `crates/trading/src/engine.rs` con `pub struct TradingEngine` y métodos `async fn` que devuelven `Result<T, TradingError>`. `TradingError` cubre `SystemNotFound{system_id}`, `InvalidTask{message}`, `TaskNotFound{task_id}` (equivalente a los `Schema.TaggedError`).
- **RPC**: constantes en `crates/rpc/src/lib.rs` (`methods::TRADING_SNAPSHOT = "TradingSnapshot"`, `TRADING_ACTION_STATE`, etc.), match arm en `crates/engine/src/rpc.rs` que deserializa params con `parse_params` y devuelve `RpcReply`. `snapshot` como **stream** `WatchTradingSnapshot` (patrón `watch::Receiver`, como `SessionsEngine::watch_sessions` en `crates/engine/src/sessions.rs:720`) o RPC unario; el plan prevé `WatchTradingSnapshot` + `TradingAction*`.
- **MCP**: `crates/mcp/src/tools.rs` (`ToolDef { name, description, input_schema, ... }`, `:39-46`) con una entrada por acción y el namespace `trading`; el guardián de escritorio pasa a una comprobación de metadata del chat (`aurea.trading`) en el motor del harness.
- **Permisos**: el `permission.assert` de OpenCode no existe en Zeron; en Aurea el prompt nativo lo cablea el orquestador (B7/UI). La firma de la tool debe aceptar un `PermissionGate` inyectado (callback async) para que el wiring decida.
- **`state` con `logs` recortado**: el tool `state` devuelve `logs[-20:]`; el snapshot RPC completo no.
