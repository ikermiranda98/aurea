# D2 — Qualify de contratos + lectura de posiciones/cuentas

## 1. Propósito

Portar la capa de datos de TWS: resolución de contratos (`getContractDetails` por `conId`), el mapeo de posiciones IBKR a la fila del dashboard, el resumen de cuenta y el ledger (precios y PnL), y la Suscripción de PnL por cuenta. Es lo que alimenta `snapshot.positions`, `open_positions`, `closable_positions` y la curva de equity.

## 2. Comportamiento exacto observado en el código TS

### 2.2 Mapeo de posiciones (`posicionDeIbkr`, `trading.ts:1184-1200`)

- `size = position.pos`; si no es finito o es 0 → **fila descartada** (`null`).
- `coste = safeNumber(position.avgCost)`; `multiplicador = Number(contract.multiplier)`; `derivado = ["FUT","FOP","OPT"].includes(secType) && multiplicador > 0`; `entry = coste !== null && derivado ? coste / multiplicador : coste` (TWS da el coste medio por contrato ya multiplicado: un MNQ corto a 28.641 lee 57.282).
- `symbol = localSymbol ?? symbol ?? String(conId ?? "?")`; `side = size > 0 ? "long" : "short"`; `size = |size|`.
- `preciosDe(coste,size,current,pnl)` (`:1204-1208`): `denom = |coste * |size||`; `pct = pnl / denom * 100`; si `pnl` o `denom` es null/0 → `pnl_pct = null`.
- `safeNumber` (`:760-761`): NaN/Infinity → null.

### 2.2 Precios del ledger (`:1212-1238`)

- `preciosIbkr: Map<cuenta, Map<localSymbol, {coste,size,current,pnl}>>`; `guardarPreciosIbkr` lo rellena desde las filas `portfolio` de `accountUpdates` (`:1367`): el stream de posiciones **no** trae precio de mercado ni PnL.
- `conPreciosIbkr` (`:1230-1238`): sólo rellena cuando `fila.current === null` (no pisa un precio ya recibido).
- `guardarPosicionesIbkr` (`:1241-1250`): por cuenta, mapea y descarta filas rotas/planas.

### 2.3 Stream de posiciones (`:1645-1668`)

- `ib.getPositions()` → `update.all` (mapa cuenta → posiciones).
- Guarda el contrato de **todas** las posiciones reportadas (aunque estén cerradas) por `localSymbol ?? symbol` con `conId` (`contratos.value`, `:1070`) → el cierre nunca tiene que adivinar la forma del contrato.
- `positions.value` = lista plana (sólo el primario); `guardarPosicionesIbkr(update.all)`; `positionKey` = `symbol:side+size` unidos; si cambia → log `trading.log.positions.snapshot`.

### 2.4 Resumen de cuenta (`asociarCuentas`, `:1325-1352`)

- `getAccountSummary("All", ACCOUNT_SUMMARY_TAGS)` con `ACCOUNT_SUMMARY_TAGS = "NetLiquidation,TotalCashBalance,CashBalance,UnrealizedPnL,RealizedPnL,AccountType,Currency,AvailableFunds,BuyingPower,ExcessLiquidity,MaintMarginReq"` (`:749-750`).
- Por cada `[id, tags]` de `update.all`: `tipo` (AccountType), `efectivo` (`TotalCashBalance` o `CashBalance`, conserva el previo si el tag viene vacío), `equity` (NetLiquidation), `fondos` (AvailableFunds), `compraPoder` (BuyingPower), `margen` (MaintMarginReq), `liquidez` (ExcessLiquidity), `actualizada = Date.now()`; `firstTagValue` (`:763-766`) = fila USD o la primera.
- `parseValue` (`:752-756`): vacío/no finito → null.
- Descubrimiento: `pushLog("account.discovered")` la primera vez; `suscribirPnl(id)` una sola vez (set `conPnl`, `:1304-1321`).

### 2.5 Ledger de account updates (`:1363-1388`)

- `getAccountUpdates()`: por cada cuenta, `portfolio` → `guardarPreciosIbkr`; `value` (summaries) → completa `tipo`, `efectivo` (`$LEDGER-TotalCashBalance` → `TotalCashBalance` → `CashBalance` → `TotalCashValue`) y `actualizada`.
- Se refresca como mucho cada 3 minutos (comentario `:1360-1362`); es la única fuente de precio de mercado y PnL no realizado.

### 2.6 PnL por cuenta (`:1304-1321`)

- `getPnL(id)` al primer avistamiento (del summary o del ledger): `pnlDia = dailyPnL`, `pnlRealizado = realizedPnL` (safeNumber).
- El orden importa: el ledger suele llegar antes que el summary; sin el `conPnl` set, la cuenta se quedaba sin PnL del día.

### 2.7 Qualify de contratos (`:2927-2957`)

- Con `contrato.exchange` vacío o `"SMART"`: `getContractDetails({conId, symbol, secType, lastTradeDateOrContractMonth, strike, right, multiplier, currency, exchange: ""})`.
- Busca el detalle cuyo `contract.conId === base.conId`; captura `minTick` en `ticksPorConId` (A4).
- `contratoParaOrden` (`:592-595`): si `lastTradeDate` tiene hora/zona, la recorta a `lastTradeDateOrContractMonth = fecha` (TWS rechaza "20261218 08:30:00 US/Central" con error 321).

### 2.8 Cuentas por enlace

- El mapa de cuentas es **por enlace** (`EnlaceIBKR.cuentas`, `:885`); el primario primero (`enlaces` insertion order, `:923`, `:1421-1423`).
- `primeraId(enlace)` (`:988-991`): el primer id en orden de Map (estable) → cuenta por defecto y destinataria de órdenes.
- `cuentaActivaEstado` (`:999-1021`): la selección si existe en cualquier enlace; si no, aviso y primer byte del primario.
- `cuentaDeMotor` (`:1027-1028`): la activa sólo si pertenece al primario; si no, el primer byte del primario.

## 3. Edge cases y condiciones de error

- **Posición rota** (size no finito o 0) → se descarta; nunca envenena los números derivados.
- **avgCost con multiplicador**: sin dividir, `entry` y `pnl_pct` salen ×multiplicador.
- **Precio ausente**: el stream de posiciones no lo trae; si el ledger aún no llegó, `current` queda null y `pnl_pct` null.
- **Tags de resumen por divisa**: se toma USD o la primera; TWS a veces omite los tags de cash → se conserva el valor previo.
- **Rechazo 321** (fecha de contrato con hora) → recortar a la fecha.
- **Rechazo 200** (contrato sin exchange) → re-resolver por `conId` (el "reparo" probado por `cierralotodo.py`).
- **Rechazo 201** (divisas) → explicación específica (`:695-697`).
- **Cuenta fantasma**: la selección persistida se conserva mientras su enlace no esté conectado con cuentas; `revalidarCuentaActiva` (`:1036-1051`) la descarta sólo cuando el enlace está conectado y ninguna cuenta es la recordada, y entonces borra `trading_meta.cuenta_activa`.
- **Dos cuentas en un login**: las posiciones se leen por cuenta; un cierre nunca usa la lista plana del login (`posicionesDeMotor`, `:1176-1180`).

## 4. Mapeo TS→Rust

- **Posiciones por cuenta**: `HashMap<String /*account*/, Vec<PositionRow>>` + `HashMap<String, HashMap<String, PriceRow>>`; el `posicionesIbkr.size > 0` decide si el mapa por cuenta sustituye a la lista plana (`abiertas`, `:4369-4377`).
- **Contratos**: `HashMap<String /*localSymbol*/, Contract>`; el qualify se hace al cerrar (lazy), no al arrancar.
- **Resumen/ledger/PnL**: streams del cliente TWS → `mpsc` o callbacks; `EstadoCuenta` con `actualizada: Option<Instant>`.
- **Qualify**: `get_contract_details(conid, ...)` en `crates/tws`, con el recorte de fecha; `minTick` se guarda en `ticksPorConId`.
- **Cuentas por enlace**: `HashMap<linkId, LinkState>` con `cuentas: HashMap<accountId, EstadoCuenta>`; la cuenta activa en `trading_meta`.
