# C1 — Port de `ghost.ts` (anillo WARP: control, día UTC, memoria /64, locks)

## 1. Propósito

Portar el motor del anillo WARP de Openbot (`packages/core/src/ghost.ts`, 836 LOC): el cerrojo compartido con el bat de escritorio, el preflight del daemon, el giro de día UTC que limpia la memoria de `/64`, la escalera de rotación con deduplicación por memoria, el pin de `opencode.ai` en `hosts` con verificación por `curl`, el monitor de sesión y el `release` que devuelve la máquina a su propia dirección. En Aurea vive en `crates/warp/`.

## 2. Comportamiento exacto observado en el código TS

### 2.1 Rutas y constantes (`ghost.ts:25-59`)

- `WARP_CLI = %ProgramFiles%\Cloudflare\Cloudflare WARP\warp-cli.exe`; si no existe, se busca con PowerShell `Get-ChildItem -Path ($env:ProgramFiles + '\Cloudflare') -Filter warp-cli.exe -Recurse` (`:182-194`).
- `HOSTS = %SystemRoot%\System32\drivers\etc\hosts`.
- `MEMORY_LOG = %USERPROFILE%\opencode-warp-ips.log`; `EVENT_LOG = %USERPROFILE%\ghost-eventos.log`; `DAY_FILE = %USERPROFILE%\ghost-dia.txt`; `HISTORY_FILE = %USERPROFILE%\ghost-historial.jsonl`; `PIN_LOG = %USERPROFILE%\ghost-pin.log`; `LOCK_FILE = %TEMP%\ghost.lock`; `EPOCH_FILE = %TEMP%\ghost.epoch`.
- `PIN_DEFAULT = "2606:4700:78::90:0:141"`; `PIN_LITERALS = [141, 140, 142]` (`:35-37`).
- `MAX_ATTEMPTS = 10`; `TRACE_TRIES = 20`; `DISCONNECT_POLLS = 4`; `DAEMON_POLLS = 6`; `LOCK_FRESH_MS = 30 * 60_000`; `WARP_VERB_TIMEOUT_MS = 30_000`; `SERVICE_CONTROL_TIMEOUT_MS = 60_000`; `POWERSHELL_TIMEOUT_MS = 30_000`; `QUICK_COMMAND_TIMEOUT_MS = 15_000`.
- `APP_IMAGES = ["opencode.exe","opencode dev.exe","openbot.exe","openbot dev.exe"]` (`:59`).

### 2.2 Cerrojo (`:375-399`)

- `createLock`: `openSync(LOCK_FILE, "wx")` + escribe el PID; si falla, no hay cerrojo.
- `librarCerrojo`: si crea → `true`. Si no: lee el PID del archivo; si es un PID vivo (`process.kill(pid,0)`) → `false` (busy). Si el `mtime` es **< 30 min** → `false`. Si no → borra y reintenta una vez.
- El cerrojo es **de un solo uso por run**: `Effect.ensuring(..., release)` lo borra al terminar (`:608-613`, `:744`).

### 2.3 Preflight y día (`:199-235`)

- `preflight(cli)`: `net start CloudflareWARP`, `net start "Cloudflare WARP"` (60 s c/u), `sleep(3s)`, `podarEventos` (recorta el log a las últimas **200** líneas, `:213-216`), y hasta 6×1 s de `warp-cli status` buscando `"Status update"`.
- `girarDia()` (`:220-228`): `hoy = new Date().toISOString().slice(0,10)`; escribe `DAY_FILE`; si el anterior no está vacío y **≠ hoy** → `erase(MEMORY_LOG)` + evento "dia UTC nuevo: memoria de /64 borrada…". La memoria deja de contar en el instante en que cambia el contador.
- `ajustarMemoria()` (`:230-235`): si hay > 60 líneas, deja las últimas **50**.

### 2.4 Escalera de rotación (`programar`, `:604-745`)

1. Sólo en `win32`; si el flag `ghost` está off → `{ok:false}` (`:562-565`).
2. `librarCerrojo`; si no → evento y `{ok:false}`.
3. `locateWarpCli`; si vacío → `{ok:false}`.
4. `preflight`; si falla → `{ok:false}`.
5. `girarDia`; `ajustarMemoria`; `warp-cli --accept-tos mode warp`.
6. `contarApp` (tasklist con `APP_IMAGES`) y `contarMonitores` (PowerShell `Get-CimInstance Win32_Process` cuyo `CommandLine` contenga `ghost.epoch` y `-WindowStyle Hidden`, excluyendo el PID propio, `:349-366`).
7. `hostPermite`: abre `HOSTS` en append para ver si se puede escribir (`:403-408`).
8. Bucle `intento = 1..10`:
   - `warp-cli disconnect`; hasta 4×1 s de `status` buscando `"Disconnected"`;
   - `warp-cli connect`;
   - `sondear()`: hasta 20 intentos de `curl -6 -s --max-time 8 https://cloudflare.com/cdn-cgi/trace`, 1 s entre intentos; parsea `ip=` y `warp=`.
   - `bucket = cubo(ip)` (primeros cuatro hextetos, `:162-178`).
   - Si `warp === "on"` y el bucket **no** está en `MEMORY_LOG` → `ganada`.
   - Si no: si hay bucket y no está, lo añade al memoria; evento por intento; si no hubo IP → rescate `registration delete` + 3 s + `--accept-tos registration new` + 5 s.
9. Sin `ganada` → `disconnect` + evento ("sin conectar" o "pool agotado") → `{ok:false}`.
10. Con `ganada`: `appendLine(MEMORY_LOG, bucket)`; `dirigirAAAA` (Resolver DNS con `1.1.1.1`, `resolve6("opencode.ai")`, timeout 4 s, 1 intento; si falla → `PIN_DEFAULT`); si no hay egress montado → veredicto solo por `curl` (`:715-718`); si hay egress → `egress.point([...resuelta, ...PIN_LITERALS])`; si ninguno responde → `despintar` si se puede y `{ok:false}`; si responde → `asegurarPin` (si `hostPermite`), `epochNueva` + `spawnMonitor` si hay app viva; evento final `rotate: /64 nuevo …` y `{ok:true, address: ganada.ip}`.

### 2.5 Pin de `hosts` (`:242-326`)

- `pinVivo`: regex multiline `/^[0-9A-Fa-f]{2}.*opencode-pin/m` sobre el texto leído en **latin1** (los bytes del usuario round-trip).
- `despintar`: lee (si falla → `false` y no escribe); borra las líneas `opencode-pin`; `ipconfig /flushdns`; relee y sólo cuenta si la línea desapareció.
- `asegurarPin`: si ya hay pin, no hace nada; `despintar`; escribe `HOSTS.bak` (latin1); candidatos = `[resuelta, ...últimas 3 de PIN_LOG, ...PIN_LITERALS]`; por cada uno: relee hosts (si falla, para), asegura salto de línea, añade `<candidato> opencode.ai # opencode-pin`, `flushdns`, `curl -6 -s --max-time 6 https://opencode.ai/cdn-cgi/trace` con **status 0**; si pasa → `PIN_LOG` + evento y termina; si no → `despintar` y, si no pudo quitar, para.

### 2.6 Monitor de sesión (`:328-344`)

- Comando PowerShell único (oculto, `-WindowStyle Hidden`): duerme 20 s; lee `%TEMP%\ghost.epoch`; bucle: si el epoch cambió → se retira; si los procesos `OpenCode/OpenCode Dev/Openbot/Openbot Dev` existen, reinicia un contador; tras 2 ciclos sin app, quita el pin de `hosts`, `flushdns`, evento, espera 10 s y, si la app sigue sin estar, `warp-cli disconnect` (deja el servicio arriba para la próxima rotación).
- `epochNueva()`: escribe `EPOCH_FILE` con dos dígitos aleatorios.

### 2.7 Estado e historial (`:435-522`)

- `estado()`: `hoy` (UTC) vs `DAY_FILE`; `memoria` sólo si el día coincide; `warp` = `missing` si no existe `warp-cli`, si no `unavailable`; `sc query CloudflareWARP` con `RUNNING|START_PENDING` → `warp-cli status`: `Status update: Connected` → `connected`, `Disconnected` → `disconnected`; `rotating = runs > 0`; `attempts = 10`; `attempt` opcional; `rotations = memoria.len()`; `current` = última memoria; `pin` = `pinVivo`.
- `historial()`: si no existe `HISTORY_FILE`, `seed(EVENT_LOG)`: parsea líneas `^\[dd/MM/yyyy HH:mm:ss\] (sesion|rotate): /64 nuevo (\S+)` del día actual y las escribe como JSONL; luego lee el fichero.
- `registrar()` (`:413-433`): una línea JSON por run con `at`, `origin` (default `manual`), `ok`, `attempts`, `durationMs`, `from` opcional, `to` (bucket) si ok.

### 2.8 Release (`soltar`, `:757-836`)

- Cerrojo; flag `ghost`; **si `hosts` no se puede leer → `{ok:false}`** (un pin podría estar sirviendo a nada); si hay pin y `hostPermite` y `despintar` fallan → `{ok:false}`; localiza `warp-cli` (si no existe, `egress.release` y `{ok:true}`); `egress.release` antes del túnel; `disconnect`; hasta 4×1 s de `status` buscando `"Disconnected"`; si no → `{ok:false}`; si sí → `{ok:true}`.

## 3. Edge cases y condiciones de error

- **Cerrojo ocupado por un run vivo** → `rotate`/`release` devuelven `ok:false` sin tocar nada.
- **Cerrojo de un run muerto pero < 30 min** → también busy (un run puede durar 10 intentos × ~3 min).
- **Sin `warp-cli`** → `rotate` `ok:false`; `release` con egress → `ok:true`.
- **Daemon que no responde** → preflight falla; no se levanta la escalera.
- **Sin IP en los 10 intentos** → rescate de re-registro en cada intento sin IP; si sigue sin IP, `disconnect` y `ok:false`.
- **Pool agotado** (los 10 buckets ya usados hoy) → `ok:false` ("pool agotado").
- **Hosts no legible** → nunca se escribe; `release` deja WARP arriba (un pin vivo apuntando a un túnel caído dejaría `opencode.ai` irresoluble).
- **Pin que no se puede quitar** → no se apila otro; `release` `ok:false`.
- **Monitor**: sólo un epoch **nuevo** lo retira; sin app viva no cuelga WARP (evita falsas alarmas).
- **Día UTC** → la memoria se limpia al cambiar el día, no al cambiar la hora local.
- **`estado` no escribe nada**: una página abierta puede sondear.

## 4. Mapeo TS→Rust

- **Módulo**: `crates/warp/` (`ghost.rs`, `lock.rs`, `pin.rs`, `history.rs`). Runtime `tokio`; los comandos externos con `tokio::process::Command` + `CREATE_NO_WINDOW` y `tokio::time::timeout` por cada timeout de la tabla.
- **Lock**: `OpenOptions::new().write(true).create_new(true)` sobre `%TEMP%\ghost.lock`; al tener el file handle abierto, el `mtime` y el PID; `pid_vivo` con `indows` (`OpenProcess`/`GetExitCodeProcess`) o `tasklist`; guard `Drop` que borra el fichero.
- **`run` con timeout** → helper `async fn run(cmd,args,timeout) -> (status, stdout)`; `curl` con `--max-time`.
- **Pin de hosts**: lectura/escritura **latin1** (bytes) → `Vec<u8>`; regex sobre `String::from_utf8_lossy` no es suficiente para round-trip: operar por líneas en bytes.
- **Monitor**: `tokio::spawn` de un `powershell -WindowStyle Hidden` (o, en Aurea, una tarea que vigile los procesos del sidecar y el epoch); el comando exacto del TS es la referencia.
- **Estado/historial**: `GhostStatus`/`GhostRun` en `crates/proto`; `warp_status`/`warp_rotate`/`warp_history` como RPCs (los cablea el orquestador, C3).
- **Día UTC**: `chrono::Utc::now().date_naive()`.

## 5. Test-oráculo

- **No hay tests de ghost en Openbot** (solo `flag.test.ts` comprueba que el flag `ghost` está off en `latest` y on en `dev`, `:48-51`, `:153`). El criterio de Lane C exige una **suite propia con locks simulados**; no hay oráculo de comportamiento.
- Portar como tests unitarios: `cubo()` (direcciones IPv6 con `::` y embebidas IPv4), `pin_vivo`/`despintar` sobre un fichero temporal, `girarDia` (cambio de fecha → memoria borrada), `ajustarMemoria` (>60 → últimas 50), `seed` del historial (regex del log de eventos), y la máquina de estados del cerrojo (crear/ocupado/viejo).
- El flag: `Flag.enabled("ghost")` se sustituye por una config de Aurea (el plan dice que el flag queda dormido; decidir con el orquestador si el anillo va on/off por defecto).
