# D3 — Órdenes (cierre a mercado + fallback OCA + cancelaciones + abort órdenes ajenas)

## 1. Propósito

Portar el camino de órdenes de TWS: lectura de órdenes abiertas, cancelación de las propias, envío de la orden de mercado opuesta, espera por estado terminal, y el fallback de dos límites OCA GTC a ±4 ticks en la rejilla del contrato. Es la contraparte TWS de A4 (los claims y veredictos viven en `crates/trading`; aquí vive el cable al API).

## 2. Comportamiento exacto observado en el código TS

### 2.1 Estado de órdenes (`trading.ts`)

- `ordenesIds: Map<orderId,{status,filled}>` (`:1073`), sembrado por `getOpenOrders()` (`:1714-1722`).
- `ordenesPropias: Set<orderId>` (`:1076`): las órdenes que envía el motor; `rechazosOrden: Map<orderId,string>` (`:1077`).
- `TERMINACIONES = {Filled, Cancelled, ApiCancelled, Inactive}` (`:2853-2858`).
- `estadoDeOrden(id)` / `llenadoDeOrden(id)` (`:2860-2865`).
- `refrescarOrden(orderId, ref, cantidad)` (`:2873-2887`):
  1. `getAllOpenOrders()` y busca `orderId ===` **y** `order.orderRef === ref`;
  2. si no está, `getExecutionDetails({clientId: String(clienteMotor)})`, filtra por `orderId` y `orderRef`, suma `shares`;
  3. `llenado >= cantidad` → `Filled`; si no, conserva el estado previo.
- `ib.errorSubject` (`:1673-1709`): si `ordenesPropias.has(reqId)` y el código está en `RECHAZOS_ORDEN` (`:583-587`: 103-169, 200-203, 312-329, 383-388) → `rechazosOrden` y `ordenesIds = {Inactive, filled}` inmediato. Los avisos **399, 2109, 10349** quedan fuera: la orden sigue viva.
- `textoErrorIb` (`:578`): `IBApiNextError` → `"<code>: <message>"`.
- Avisos de farm 2100-2199 → nivel `info` (`:1699-1707`).

### 2.2 Orden de cierre (`:3047-3057`)

```
{
  action: accion,                 // SELL si long, BUY si short
  totalQuantity: cantidad,
  orderType: OrderType.MKT,
  tif: TimeInForce.DAY,
  orderRef: `escritorio-cierre-${conId}-${sello}`,  // sello = Date.now()
  outsideRth: true,
  transmit: true,                 // obligatorio
  account: cuenta,
}
```
- `transmit: true` explícito: la librería manda un flag vacío como "hold, don't transmit" y TWS lo descarta con error 202 (`:3044-3046`).
- `ib.placeNewOrder(contrato, orden)`; `ordenesPropias.add(id)`.

### 2.3 Cancelaciones (`:2974-3016`)

- `activasDeEste(orden)` = `contract.conId === conId` y status no terminal.
- `propiaRef(orden)` = `orderRef` empieza en `escritorio-cierre`.
- `ajenas = pendientes.filter(!propiaRef)` → si hay, aborta con `trading.close.foreign_orders` **antes** de cancelar nada.
- Propias: `ib.cancelOrder(orderId)` por cada una, `sleep(500)`, relee `getAllOpenOrders`; si quedan → `trading.close.cancel_pending` (no enviar).

### 2.4 Fallback OCA (`:3167-3229`)

- `salto = tick * 4`; `arriba/abajo = enRejilla(precio ± salto, tick)`; exige `abajo > 0 && arriba > abajo`.
- Cada límite: `LMT`, `tif GTC`, `orderRef = escritorio-cierre-limite-<conId>-<sello>`, `outsideRth: true`, `ocaGroup = cierre-<conId>-<sello>`, `ocaType: 1`, `transmit: true`, `account`.
- `sleep(500)` y `refrescarOrden` por cada intento; `aceptados` = los que siguen sin estado terminal.
- Veredictos: 0 aceptados y ninguno con id → `market_failed_no_limits`; con ids rechazados → `market_failed_limits_rejected`; 1 → `ok` con un límite; 2 → `ok` con OCA.

### 2.5 Espera de la orden de mercado (`:3069-3128`)

- Hasta 20 pasos de 250 ms con `refrescarOrden`; `posiciónFuera()` (la fila desaparece del stream de posiciones) cuenta como `Filled` aunque el estado de la orden se retrase.
- Si no es `Filled` pero sigue viva/desconocida: `ib.cancelOrder(idMercado)` y otros 20×250 ms; `Filled`/`posiciónFuera` → `executed_order`; si no → `market_not_cancelled` (sin límites).

### 2.6 Rechazos y avisos

- `RECHAZO_DIVISAS = /expose account to currency leverage/i` → `EXPLICACION_DIVISAS` (`:695-697`).
- 502 + ECONNREFUSED → "TWS is not accepting connections… retrying every 5 s" (`:1690-1691`).
- El `errorSubject` debouncea avisos idénticos durante 60 s (`avisoIbkr`, `:1672`, `:1696-1698`).

## 3. Edge cases y condiciones de error

- **ID de orden por sesión**: los orderId se reinician en cada sesión de TWS → el emparejamiento es siempre por `(orderId, orderRef)`; las ejecuciones por `clientId` + `orderRef`.
- **Límite fuera de rejilla** → TWS lo rechaza; por eso `enRejilla`.
- **`transmit` ausente** → error 202 y la orden nunca sale.
- **Rejected propio** → `Inactive` inmediato, no esperar el poll.
- **Warning 399/2109/10349** → no marcar como rechazo.
- ** Órdenes ajenas** → abortar sin cancelar (protege stops manuales o de bots).
- **Cancelación no confirmada** → abortar sin enviar.
- **Doble cierre**: los límites OCA sólo salen tras un estado terminal positivo del mercado (o su cancelación confirmada).
- **TWS ocupado** → reintentos de reconexión; las órdenes en vuelo no se dan por perdidas.

## 4. Mapeo TS→Rust

- **`crates/tws`** expone: `get_all_open_orders()`, `place_new_order(contract, order)`, `cancel_order(id)`, `get_execution_details(client_id)`, `get_contract_details(...)`, `get_positions()`, `get_account_updates()`, `get_account_summary()`, `get_pnl(account)`.
- **Orden**: struct `Order { action, total_quantity, order_type, tif, order_ref, outside_rth, transmit, account, lmt_price, aux_price, oca_group, oca_type }` serializable al framing de TWS (campo `orderRef`, `account`, `openClose`, `origin`).
- **Estado**: `ordenes_ids: Mutex<HashMap<i32, OrderState>>`; `ordenes_propias: HashSet<i32>`; `rechazos: HashMap<i32,String>`.
- **Espera**: bucle `tokio::select!` con `tokio::time::sleep(250ms)`; `posición_fuera` consulta el estado de posiciones (D2).
- **Refrescar**: `get_all_open_orders` + `get_execution_details`; nunca confiar solo en el estado cacheado.
- **Ticks**: `en_rejilla`, `texto_precio`, `tick_de_contrato` (A4) — la `minTick` llega del `get_contract_details` del cierre.
