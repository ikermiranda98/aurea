# A1 — Pool de sistemas + snapshot síncrono + store SQLite

## 1. Propósito

Portar el corazón estático del motor de Openbot: el escaneo del pool de sistemas (`NN_name/`), el dossier de cada sistema leído de sus propios ficheros (`config.py`, `reglas.json`, `system.json`), el estado en memoria que alimenta `snapshot()`, y el store SQLite de 8 tablas (`sql.ts`) con sus migraciones. Es la base de la que colgarán el ciclo de vida (A2), los cierres (A4) y las tasks (A5); no toca TWS ni MT5.

> **Hallazgo crítico de conteo:** el plan y el Anexo A dicen "7 tablas", pero `trading/sql.ts` exporta **8**: `TradingTaskTable`, `TradingTradeTable`, `TradingLinkTable`, `TradingMetaTable`, `TradingAccountTable`, `TradingBotOrderTable`, `TradingBotFillTable`, `TradingCloseTable` (`trading/sql.ts:5,22,38,58,69,83,98,115`). El plan lista los 8 nombres pero dice 7. El port debe crear 8 tablas.

## 2. Comportamiento exacto observado en el código TS

### 2.1 Escaneo del pool

- `escanearCarpetas(dir)` (`trading.ts:338-345`): `readdir(dir, {withFileTypes:true})`, filtra `entry.isDirectory() && /^\d\d_/.test(entry.name)`, ordena lexicográfico. Un error de lectura → lista vacía.
- `definicion(name, dir)` (`trading.ts:355-386`) construye el dossier:
  - `id = name.slice(0, 2)` (los dos dígitos).
  - `config.py` (lectura tolerant, `""` si falta): `CLIENT_ID` con `/^CLIENT_ID\s*=\s*(\d+)/m`; `HOST` con `/^HOST\s*=\s*"([^"]+)"/m`; `PUERTO` con `/^PUERTO\s*=\s*(\d+)/m`; `HORA_CIERRE` con `/^\s*HORA_CIERRE\s*=\s*\((\d+),\s*(\d+)(?:,\s*(\d+))?\)/m` → `"HH:MM"` o `"HH:MM:SS"` (padded a 2).
  - `servidor = HOST:PUERTO` sólo si ambos existen (`:379`).
  - `reglas.json`: `{idea?: string, reglas?: Record<string,string>}`; sólo entradas de tipo string (`:366-373`).
  - `meta` desde el mapa `META` fijo (`:250-266`): 15 carpetas conocidas con `symbol`/`timeframe` (NQ 5m/30m/15m/1h, GC 30m/15m/1h, RTY 2h/1h/4h, USDJPY 1h/1h/1h/1h/3h). Carpeta no listada → `meta = null`.
  - `mt5` desde `system.json` (`leerDestinoMT5`, `:302-317`): JSON con BOM opcional; `broker` debe ser `"mt5"` (lower); `login` safe int > 0 o null; `server`/`symbol` string no vacía o null; `magic` safe int > 0 o `magicPorDefecto(id)`.
- `magicPorDefecto(sistema)` (`bots-mt5.ts:171`): `7_700_000 + parseInt(sistema, 10)`.
- `escanearArranque()` (`:2157-2208`): pone `sistemas = []`, `bots.clear()`, `pnlBots.clear()`; si no hay carpeta → log `trading.log.pool.no_folder` y vacío; si no hay `NN_name` → `trading.log.pool.no_systems`; si hay, define todos, avisa de `CLIENT_ID` compartido (agrupa por `clientId`, `:2176-2185`), avisa de `config.py` que apunta a otro `host:puerto` que el motor (`:2186-2189`), resuelve `pythonw` con `where pythonw` (`:2190-2191`), crea un `Runtime` por sistema con `registroOffset = offsetDeHoy(registro.log)` y `consolaOffset = cola(consola.log)`, luego `sondear(true)` y `ingestaUna(def, false)` para todos.
- `offsetDeHoy(path)` (`:1955-1960`): offset en bytes de la primera fila con prefijo de fecha local `YYYY-MM-DD `; si no existe, el tamaño del fichero. Garantiza que un reinicio no repita sesiones anteriores.
- `cola(path)` (`:1803-1810`): tamaño o 0 si no existe.

### 2.2 Store SQLite (`trading/sql.ts`, 8 tablas)

- `trading_task` (`:5-16`): `id` PK, `kind`, `system_ids` JSON array not null, `run_at` int, `status` default `pending`, `resolved_at` nullable, timestamps.
- `trading_trade` (`:22-32`): `id` PK `system:ts:<sha1(message)[0..12]>`, `system`, `ts`, `pnl` real nullable, `message`.
- `trading_link` (`:38-54`): `id` PK (`host:port` o `mt5-<login>@<server>`), `host`, `port` (0 para MT5), `label`, `broker` default `ibkr`, `mt5_login`, `mt5_server`.
- `trading_meta` (`:58-62`): clave/valor. Claves usadas: `client_id` (`:798`), `cuenta_activa` (`:1049`), `carpeta-sistemas` (`:3767`), `bucle-motor` (`:2747`), `bot-token:<id>` (`:1594`), `bots-mt5-instrumentos` (`:1515`).
- `trading_account` (`:69-78`): `id` PK, `link_id`, `tipo` nullable.
- `trading_bot_order` (`:83-95`): `id` int PK (orderId IB), `system`, `status`, `data` JSON (`OrdenVirtual`), `updated`.
- `trading_bot_fill` (`:98-107`): `id` PK `"<deal>.<orderId>"`, `system`, `time`, `data` JSON (`Ejecucion`).
- `trading_close` (`:115-135`): `id` PK, `symbol`, `lock` nullable, `verdict` nullable, `ts`; **uniqueIndex `trading_close_lock_idx` sobre `lock`** (SQLite cuenta NULLs como distintos: filas con veredicto y la fila masa nunca colisionan).

### 2.3 Estado en memoria y `snapshot()`

- Estructuras (`:689-692`, `:1067-1084`): `sistemas: Definicion[]`, `bots: Map<id, Runtime>`, `pnlBots: Map<id, number>`, `positions.value`, `contratos: Map<localSymbol, Contract>`, `ordenesIds: Map<orderId,{status,filled}>`, `ordenesPropias: Set<orderId>`, `rechazosOrden`, `logs.value`, `tasks.value`, `trades.value`.
- `toSchemaSystem` (`:715-734`): `running = active = startedAt !== null`; `pid`, `started_at`, `symbol`/`timeframe` desde `meta` o `"?"`, `pnl_day`, `client_id`, `close_hour`, `last_activity_at`, `description`, `rules` (copia).
- `pushLog` (`:1109-1136`): ring de **800** entradas; sin `extra` (motor) aplica debounce de **60 s** por `level\1system\1message`; con `extra.ts` no.
- `trades`: arranca del DB con las 200 más recientes (`:1087-1089`); `registrarTrades` inserta con `onConflictDoNothing`, dedupe en memoria por `system+ts` y ring ordenado desc capped a **200** (`:2022-2057`).
- `tasks`: `refreshTasks` lee las 50 más nuevas (`order by time_created desc, run_at desc`, `:2557-2566`).
- `equity`: muestreo cada **15 s** por cuenta, cap **1000** puntos (`:2542-2554`).
- `snapshot()` (`:4391-4421`): `version = "nativo-1"` (`:737`), `connected = primary.conectado && primary.ocupado === null`, `client_in_use` opcional, `account`, `systems`, `positions` (vista), `open_positions`, `closable_positions`, `logs`, `tasks`, `trades`, `equity`, `accounts`, `links`, `systems_dir`, `programs` opcional.
- `abiertas()` (`:4369-4377`): si `posicionesIbkr.size > 0` usa el mapa por cuenta (todo el login), si no la lista plana; más las posiciones de los enlaces MT5 conectados; filtra `size > 0`.
- `cerrables()` (`:4384-4389`): `posicionesDeMotor(cuentaDeMotor())` + posiciones de enlaces MT5 conectados, `size > 0`. Las cuentas watch quedan fuera.
- `lecturaVista()` (`:4347-4363`): si la cuenta activa es MT5 → sus posiciones y cierres; si IBKR → `posicionesIbkr.get(id)` con precios del ledger superpuestos (sólo si `current === null`), y la curva siempre de la cuenta activa.
- `cuentaActivaEstado` (`:999-1021`): la selección mientras exista en algún enlace; si no, aviso `trading.log.account.active_absent` y cae al primer byte del enlace primario. `cuentaDeMotor` (`:1027-1028`): la activa sólo si pertenece al enlace primario; si no, el primer byte del primario.
- `sincronizarCuentas` (`:2697-2731`): escribe/actualiza `trading_account` por cada id descubierto (el más viejo primero, el primario primero) y **borra las filas cuyo `link_id` ya no está en el registro** (aunque el espejo no las tuviera).

### 2.4 Identidad de ts y borrado

- `tradeIdentidad` (`:771-772`): `` `${system}:${ts}:${sha1(message).slice(0,12)}` `` → replay del log no duplica.
- `safeNumber` (`:760-761`) y `parseValue` (`:752-756`): nada de NaN/Infinity; null.
- `toSchemaAccountDe` (`:3858-3871`): `type = "${tipo} · IBKR ${id.startsWith("DU") ? "demo" : "live"} (${puerto})"`.

## 3. Edge cases y condiciones de error

- Carpeta de pool inexistente o sin `NN_name` → pool vacío con log honesto (`:2163-2170`); nunca una ruta personal por defecto (AE-009, test `:549-554`).
- `config.py` o `reglas.json` inválidos → hechos a null, el bot arranca igual (`:351-354`).
- `system.json` con `broker` distinto de `mt5` → `mt5 = null` (el bot va a TWS).
- `magic` ausente/inválido → `magicPorDefecto(id)`.
- `CLIENT_ID` compartido por dos sistemas → warning (`:2184`); TWS rechazaría al segundo.
- `config.py` apuntando a otro `host:puerto` → warning (`:2188`); el sweep no verá ese bot.
- `trading_meta` caída: el `client_id` degrada a 30 (`:814`); el resto de lecturas de arranque propagan el fallo al log de arranque (`:3837-3840`).
- `cuentaActiva` persistida que ya no existe en ningún enlace: se mantiene hasta que el enlace que la poseía esté conectado con cuentas y ninguna sea ella (`revalidarCuentaActiva`, `:1036-1051`); entonces se borra de `trading_meta`.
- Números de IB rotos → null (`safeNumber`), nunca 0 inventado.

## 4. Mapeo TS→Rust

- **Efecto/Layer** → un `TradingEngine` construido una vez (`Arc`), con estado en `parking_lot::RwLock<Inner>` o `tokio::sync::watch` para la snapshot. `snapshot()` es lectura síncrona: en Rust un `RwLockReadGuard` clonado a un `Snapshot` (estructura `crates/proto`).
- **`Effect.Stream`/`escuchar`** → tareas `tokio::spawn` con resubscripción cada 5 s (`trading.ts:1155-1165`); el estado compartido se actualiza por `mpsc`/`watch`.
- **Tablas** → `rusqlite` (ya es dependencia del workspace `0.32` bundled, `Cargo.toml:152`; usado en `crates/engine` y `crates/sync`). Migraciones como constantes `SQL` en `crates/trading/src/store.rs`, aplicadas al arrancar (`user_version` o `CREATE TABLE IF NOT EXISTS` + `PRAGMA`). Equivalente de `onConflictDoNothing` → `INSERT OR IGNORE`; `onConflictDoUpdate` → `INSERT ... ON CONFLICT(id) DO UPDATE SET ...`; `returning()` → `RETURNING` (rusqlite lo soporta con `query_row`).
- **`trading_close.lock` único** → `CREATE UNIQUE INDEX trading_close_lock_idx ON trading_close(lock)`; en SQLite los NULL no colisionan, igual que drizzle.
- **`Definicion`/`System`/`Snapshot`** → structs en `crates/proto` (serializables con `serde`), para que RPC/MCP/UI compartan el mismo tipo.
- **Journaling** → no aplica a A1; pero el patrón de journal reanudable de `crates/engine/src/run_journal.rs` (`append`, `replay`, `flush`) es la referencia para A4 si se quiere durable el ciclo de cierre (aunque el código TS usa `trading_close`, no un journal).
- **Credenciales broker** → reutilizar `crates/engine/src/credentials.rs` (`BrokerConfig`, `CredentialBroker`) para slots IBKR/MT5; A1 sólo lee `client_id`/tokens de `trading_meta`.
