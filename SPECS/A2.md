# A2 — Ciclo de vida de bots (spawn/adoptar/pid-guard/kill) + servidor-bots HTTP

## 1. Propósito

Portar el ciclo de vida completo de los procesos bot: arranque (`pythonw bot.py`), adopción de bots vivos externos vía `panel.pid`/TWS, barrido cada 45 s, parada con pid-guard de tres vías, y la API HTTP local `127.0.0.1` `/bot/*` que sustituye a TWS para los bots MT5. Incluye la ingesta de `registro.log`/`consola.log` y la recolección de trades.

## 2. Comportamiento exacto observado en el código TS

### 2.1 Runtime por sistema

`Runtime` (`trading.ts:319-335`): `source: "panel"|"external"|null`, `pid`, `startedAt`, `child: ChildProcess|null`, `planeado` (parada ya contabilizada), `sondeoDudado`, `registroOffset`, `consolaOffset`, `ultimaActividad`. `runtimeNuevo()` (`:1932-1942`) inicia todo a null/0.

### 2.2 Utilidades de proceso en Windows

- `ejecutalo(ruta, args, timeout)` (`:391-407`): `spawn` con `windowsHide`, sólo lee stdout, mata al superar el timeout, resuelve aunque falle el spawn. **Nunca `spawnSync`**: nada en la ruta de parada bloquea el event loop.
- `pidVivo(pid)` (`:413-418`): `tasklist /FI "PID eq <pid>" /NH /FO CSV` (5 s); salida vacía → `null` (no se pudo comprobar); contiene `"<pid>"` → `true`; si no → `false`.
- `rutaPlana(ruta)` (`:422`): lowercase, `/`→`\`, colapsa `\\+`; una ruta con `..\\` simplemente falla el prefijo (fail-closed).
- `pidEsBot(pid, dir)` (`:435-459`): PowerShell `Get-CimInstance Win32_Process -Filter "ProcessId=<pid>" | Select-Object -ExpandProperty CommandLine` (8 s). Salida vacía → `null`. No contiene `bot.py` → `false`. Con `dir`:
  1. si `panel.pid` del sistema == pid → `true`;
  2. si `panel.pid` no está vacío → `false`;
  3. extrae la ruta de `bot.py` (regex `"([^"]*bot\.py)"` o `([^\s"]*bot\.py)`) y exige `rutaPlana(ruta).startsWith(rutaPlana(dir) + "\\")`.
  Sin `dir`: exige que la línea contenga `pythonw`.
- `abrir` de programas (`trading/programas.ts:130-137`) no aplica a bots.

### 2.3 Arranque (`arrancarNucleo`, `:2215-2376`)

1. `def = sistemas.find(id)`; si no → `SystemNotFoundError`.
2. Si ya `startedAt !== null` → `{ok:true}` (idempotente).
3. Si `def.dir === null` → `{ok:false, motivo:"la carpeta del sistema no está disponible"}`.
4. `arranquesEnVuelo: Set<string>` (`:349`): un segundo arranque en vuelo → `{ok:false, motivo:"ya hay un arranque en marcha"}`; se libera con `Effect.ensuring` (`:2374`).
5. **Adopción preventiva**: si el sistema no es MT5 y el primario está conectado y tiene `clientId`, llama `clientIdEnUso(host,port,clientId)` (`:598-616`, conexión IB de 2,5 s que vigila `errorSubject` por código **326** o `/already in use/i`); si está ocupado → `adjuntar(def,"external",null,...)` y `ok:true` sin spawn.
6. Aviso de gemelo: otro sistema con el mismo `meta.symbol` arrancado → warning `trading.log.bot.same_symbol` (`:2249-2263`), pero el arranque continúa.
7. Entorno MT5 (`:2267-2293`): `enlaceBot(id)` resuelve el enlace; `prepararBots()`; `tokenDe(id)`; `entornoMT5 = { PYTHONPATH: "<datosBots>\\pyshim;<botPythonPath>", PYTHONIOENCODING:"utf-8", OPENBOT_BOT_TOKEN, OPENBOT_ENGINE_URL, OPENBOT_ENGINE_FILE, OPENBOT_SYSTEM_ID, OPENBOT_MAGIC }`.
8. Si no hay `previo`, siembra offsets (`registroOffset = offsetDeHoy`, `consolaOffset = cola`).
9. Abre `consola.log` en modo append (`:2301-2310`); si falla → `ok:false`.
10. `spawn(pythonwEjecutable, ["<dir>\\bot.py"], { cwd: dir, env: {...process.env, PYTHONPATH: botPythonPath ?? "", ...entornoMT5}, windowsHide: true, stdio: ["ignore","ignore", consola.fd] })` (`:2313-2318`). `pythonwEjecutable` se resuelve en el arranque con `where pythonw` (`:2190-2191`), defecto `"pythonw"`.
11. `child.on("error")` (`:2322-2332`): limpia `child/source/pid/startedAt` y log `trading.log.bot.start_failed`.
12. `child.pid === undefined` → `ok:false` (`:2333-2336`).
13. `child.on("exit")` (`:2337-2356`): si `actual.child !== child` ignora; `child=null`; si `planeado` → no reporta caída; si no, limpia y hace la última ingesta (`ingestaUna(def,false)`); código 0 → `trading.log.bot.stopped_self`, si no → `trading.log.bot.crashed`.
14. `runtime.child/source/pid/startedAt` y escribe `panel.pid` (`:2357-2363`).
15. Log `trading.log.bot.started_user` / `started_task` (`:2364-2371`).

### 2.4 Barrido (`sondear`, `:2064-2153`)

- Cadencia: 45 s (`:2066`), o forzado en arranque (`escanearArranque`).
- Si el sistema tiene `startedAt` y `child === null` (adoptado): `pidVivo(pid)`; `null` → se queda y avisa una vez (`sondeoDudado`); `false`/`pidEsBot` no → se sienta (`source/pid/startedAt = null`), ingesta final y log `probe_reused`/`probe_down`; `pidEsBot === null` → se queda y avisa.
- Si no está arrancado: lee `panel.pid`; si `pid > 0` y `pidVivo` no es null: si vivo y `pidEsBot === true` → `adjuntar(def,"panel",pid,...)`; si `null` → se queda; si `false` → cae al borrado del marcador. Si `pid > 0` → `unlink(panel.pid)`. Si `def.clientId !== null` y `clientIdEnUso(host,port,clientId)` → `adjuntar(def,"external",null,...)`.
- `adjuntar` (`:1963-1975`): idempotente; si ya tenía `startedAt` sólo actualiza source/pid/planeado; si no, `startedAt = Date.now()` y **borra `pnlBots`** (el pnl del día se reinicia al adjuntar).

### 2.5 Parada (`pararBot`, `:2385-2507`)

- Si no está arrancado → `{stopped:true}`.
- Si `child === null && pid === null` → `{stopped:false, motivo:"externo sin PID (lo arrancó otra instancia)"}` + warning.
- Con `child`: `runtime.planeado = true; child.kill(); sleep(300); pidVivo(hijo)`:
  - `null` → `planeado=false`, `{stopped:false}` ("no se pudo confirmar").
  - `true` → `planeado=false`, `{stopped:false}` ("el proceso sigue vivo").
- Con pid adoptado: `pidVivo` → `null` ⇒ no se mata nada; `true` ⇒ `pidEsBot(pid, dir)`; `false` ⇒ limpia runtime + `unlink(panel.pid)` y `{stopped:true}` (pid reciclado o bot caído); `null` ⇒ no se mata nada; `true` ⇒ `taskkill /PID <pid> /T /F` (8 s) y `pidVivo` de confirmación (`null` ⇒ sin veredicto; `true` ⇒ fallo).
- Al final: limpia `child/source/pid/startedAt/planeado`, `unlink(panel.pid)`, log `STOP_ORIGIN_MESSAGE[origin]` (`:174-178`: user/task/panic).
- `detener` (`:2509-2515`): si `stopped`, llama `traductor.sistemaParado(id)` (cancela las órdenes de mercado MT5 que quedaran esperando).
- `detenerTodos` (`:2519-2536`): itere en orden; un fallo no detiene el resto; acumula `detenidos`/`fallos` y log `trading.log.bot.stop_failed`.

### 2.6 Ingesta de logs (`ingestaUna`, `:1980-2015`; `parsearChunk`, `:1877-1930`)

- Lee `registro.log` y `consola.log` desde el offset (máx 1 MB por lectura, `leerCola` `:1813-1826`); actualiza offset al size.
- `LINEA_BOT = /^(\d{4})-(\d{2})-(\d{2}) (\d{2}):(\d{2}):(\d{2}),(\d{3}) (.+)$/` (`:1829`); `tsDe` construye Date local.
- `SORRO` (`:1833-1834`) descarta `updatePortfolio:`, `Warning N`, `Disconnecting`, `position: `, `Connecting`, `Connected`, `Logged on`, `API connection`, `Synchronization`, `connectRequest`, `commissionReport:`, `execDetails `, `openOrder:`, `orderStatus:`; pero si `esDelSistema` y `cosecha`, recoge `unrealizedPNL=<n>` en `pnlBots` (`:1893-1897`).
- `CICLO` (`:1836`) conserva `conectado a|contrato:|contexto:|la estrategia ha terminado|desconectado|el bot ha arrancado|Hoy no |Error \d`.
- Eventos: `DENTRO a |PROMEDIA a ` → `open`; `FUERA|posición cerrada` → `close`; `señal (COMPRA|VENTA)` → `signal`. En `close`, `pnlBots` = cifra de `\(([-+0-9.]+) USD brutos\)` y la fila pasa a `cierres` (trade) (`:1905-1911`).
- `nivelError` (`:1865-1870`): `Error 1100|1101|1102` → warning; otro `Error N` → error; `Traceback|Exception` → error.
- Continuaciones con indentación (`/^\s/`) se pegan al latido anterior; `Traceback|Exception` sin timestamp hereda el último ts.
- `RECHAZO_DIVISAS` añade el latido explicativo (`:695-697`, `:1913`, `:1927`).
- `registrarTrades` (`:2022-2057`): insert si nuevo + ring 200.

### 2.7 Servidor-bots (`trading/servidor-bots.ts`, 113 líneas)

- `createServer` + `listen(0, "127.0.0.1")` → puerto libre (`:106`); `url = http://127.0.0.1:<puerto>`.
- Header `x-openbot-bot`; si el token mide < 16 o `sistemaDeToken` no lo resuelve → **401** `{error:"token de bot inválido"}` (`:72-74`).
- Rutas (`:77-100`): `GET /bot/hello`, `POST /bot/qualify`, `POST /bot/bars`, `POST /bot/order`, `POST /bot/cancel`, `GET /bot/orders`, `GET /bot/fills`, `GET /bot/positions`, `GET /bot/account`; desconocida → **404**. Excepción → **409** `{error}` (`:101-103`).
- Esquemas Effect (`:11-46`): `Contrato`, `Velas`, `Orden`, `Cancelar`.
- `prepararBots` (`trading.ts:1610-1632`): escribe `pyshim/ib_async/__init__.py` (`IB_ASYNC_INIT`), `pyshim/ib_async/util.py` (`IB_ASYNC_UTIL`), `pyshim/ib_insync/__init__.py` (`IB_INSYNC_INIT`); arranca el servidor; escribe `engine.json` `{api, pid}`; arranca `setInterval(traductor.tick, 1000)` (unref).
- `engine.json` (`:830`, `:1622`) es el mecanismo de re-conexión del pyshim tras un reinicio de la app.
- Tokens (`:1582-1604`): `bot-token:<id>` en `trading_meta`, `randomBytes(24).toString("hex")`; `sistemaDeToken` es barrido lineal del mapa.

## 3. Edge cases y condiciones de error

- **Respuestas de tres vías** (`true`/`false`/`null`) en `pidVivo` y `pidEsBot`: `null` nunca es un "no". Matar o retirar un asiento con respuesta no verificada deja un bot vivo fuera del panel y del panic; el código siempre conserva el asiento y avisa una vez (`sondeoDudado`).
- `panel.pid` obsoleto con pid reciclado por otro proceso → no se mata; se limpia y se reporta `pid_reused` (`:2440-2458`).
- `taskkill` falla o no se puede confirmar → `stopped:false` (el panel y el panic lo tratan como vivo).
- `child.kill()` no confirma en 300 ms → `stopped:false`, `planeado` restaurado a false.
- `spawn` sin `pid` → fallo honesto, no "running para siempre".
- `arranquesEnVuelo` evita dos procesos gemelos por sistema.
- `clientIdEnUso` evita el gemelo TWS (un segundo spawn con el mismo client id sería rechazado).
- `where pythonw` ausente → degrada al comando desnudo `pythonw` (`:817`, `:2190-2191`).
- Servidor-bots: token corto/inválido → 401; el stand-in de `ib_async` convierte `{error}` en excepciones `ib_async`.
- `consola.log` no abrible → el bot no arranca (`:2309-2310`).

## 4. Mapeo TS→Rust

- `spawn` → `std::process::Command` con `creation_flags(CREATE_NO_WINDOW)`, `stdin/out/err` configurados; el `consola.log` se abre con `OpenOptions::append` y se pasa como `Stdio::from(file)`. `child.kill()` → `Child::kill` (async en tokio).
- `pidVivo` → `tasklist` vía `tokio::process::Command`; parseo CSV.
- `pidEsBot` → PowerShell `Get-CimInstance Win32_Process` (o el crate `windows` con WMI/`Win32_Process`). El comando exacto y los regex deben conservarse (`:442`, `:453-456`).
- `ejecutalo` → helper async con `tokio::time::timeout` y kill al expirar; nunca síncrono.
- `Effect.sleep(300)` → `tokio::time::sleep(Duration::from_millis(300))`.
- `servidor-bots` → `tokio::net::TcpListener::bind("127.0.0.1:0")` + `axum`/`hyper`; el token se resuelve en un `HashMap<&str, systemId>`; el body se limita y se decodifica con `serde_json` + validación manual equivalente a los Effect Schema.
- `pyshim` → recursos embebidos (`include_str!` de `bots-py.ts`) escritos a `%APPDATA%\Aurea\bots-mt5\pyshim` (plan §5.2); `engine.json` se escribe con `{"api": url, "pid": pid}`.
- `arranquesEnVuelo` → `Mutex<HashSet<String>>`; `bots` → `Mutex<HashMap<String, Runtime>>`.
- Los offsets de cola → `u64`; la ingesta en una tarea por sistema o una tarea única que recorra el pool.
- `traductor.sistemaParado` y el `tick` de 1 s → el traductor MT5 (A3) expone `sistema_parado`/`tick`; el intervalo con `tokio::time::interval`.

## 6. Criterio de aceptación

> **A2** Ciclo de vida de bots: `arrancar/arrancarNucleo` (spawn `pythonw bot.py`, adopción vía `panel.pid`), `pararBot/detener/detenerTodos` con pid-guard (CommandLine contiene `bot.py` en la carpeta del sistema), servidor-bots HTTP `/bot/*` con header por sistema. *Criterio: sección lifecycle de `trading-engine.test.ts` pasa en Rust.*

(Nota: el test-oráculo de ciclo de vida real es `trading-bots-mt5.test.ts` e2e; `trading-engine.test.ts` no tiene procesos reales. Portar ambos.)
